PEF Apple Watch Native App
WatchLogger — Universeller Sensor-Logger für watchOS

Eine native watchOS-App zur automatischen Symptomerkennung und manuellen Eingabe — entwickelt für Parkinson-Monitoring, aber bewusst so gebaut, dass sie jeden beliebigen REST-Endpoint ansprechen kann. Endpoint-URL, Auth-Header und Metrik-Mapping sind vollständig per JSON-Config steuerbar — kein PEF erforderlich.

🙋
Wir suchen Contributor! Dieses Dokument ist eine Anforderungsspezifikation für eine native watchOS-App. Die App wird bewusst als universeller REST-Logger gebaut — nicht als PEF-exklusives Tool. Jeder der einen REST-Endpoint betreibt soll sie nutzen können. Der Autor hat kein macOS-Gerät — wir suchen Swift/watchOS-Entwickler die das Projekt umsetzen oder dazu beitragen möchten.

1. Projektkontext & Motivation

1.1 Ausgangssituation

Das PEF-Projekt (Parkinson Erfassungs-Frontend) ist eine Webanwendung zur Erfassung von Parkinson-Symptomen, die als Open-Source veröffentlicht werden soll — die Entwicklung findet aktuell noch in einem privaten Repository statt. Das Backend basiert auf FastAPI + PostgreSQL, das Frontend auf Vanilla JavaScript. Für die Erfassung direkt am Handgelenk existiert eine Progressive Web App (PWA) unter /watch/.

Limitierungen der aktuellen PWA-Lösung:

  • Kein nativer Zugriff auf CoreMotion (Accelerometer, Gyroscope mit voller Auflösung)
  • Kein HealthKit-Zugriff aus dem Browser
  • Keine Background-Tasks — App muss aktiv geöffnet sein
  • Keine Watch-Face-Complications
  • Safari existiert auf watchOS nicht — die PWA läuft nur auf dem iPhone
  • Kein haptisches Feedback mit erweiterten Patterns

1.2 Ziele

  • Symptome passiv erkennen (Tremor, Gangbild, HRV) ohne Nutzerinteraktion
  • Manuelle Eingaben per Sprache oder Touch ermöglichen
  • Vollständig konfigurierbar — Endpoint, Auth, Metriken, Button-Labels per JSON
  • PEF-unabhängig — generischer Sensor-Logger für beliebige REST-Backends
  • Offline-fähig — lokaler Puffer, automatische Synchronisation
  • Open Source — wird nach MVP als Community-Projekt unter MIT-Lizenz veröffentlicht (aktuell private Entwicklung)
💡
Kernidee Statt "Patient muss aktiv 4 Buttons tippen" → "Watch erkennt Tremor-Episode automatisch, fragt kurz nach Bestätigung, loggt selbstständig." Das ist der eigentliche Mehrwert gegenüber der PWA.

3.3 PEF Pairing-Flow

Kompatibel mit dem bestehenden PEF-Pairing-System:

  1. Watch zeigt 8-stelligen Nonce-Code (GET /api/auth/pairing/request-nonce)
  2. Nutzer gibt Code im PEF-Webinterface ein (POST /api/auth/pairing/link-token)
  3. PEF-Backend gibt JWT zurück
  4. Watch speichert Token im Keychain, alle folgenden Requests mit Authorization: Bearer

4. Sensor-Datenerfassung

4.1 Tremor-Erkennung

Automatische Erkennung von Parkinson-typischem Ruhetremor (4–6 Hz) ohne Nutzerinteraktion.

CoreMotion → Accelerometer (100Hz) → Ringpuffer (512 Samples / 5s) → FFT (vDSP_fft_zrip, 256 Punkte) → Frequenzband-Analyse (3–8 Hz) → Peak bei 4–6 Hz AND Amplitude > 0.15g → Tremor-Event mit Confidence-Score (0.0–1.0)

Hysterese: Tremor-Start wenn 3 aufeinanderfolgende FFT-Frames über Schwellwert; Tremor-Ende wenn 5 Frames darunter.

Unterscheidung: 4–6 Hz = Parkinson-Ruhetremor; 8–12 Hz = Essentieller Tremor — beide erkennbar und unterscheidbar im Frequenzspektrum.

// Output-Event
{
  "type": "tremor_detected",

  "duration_s": 15,
  "dominant_frequency_hz": 4.8,

}

4.3 Herzratenvariabilität (HRV)

  • Passiv: HKObserverQuery — Watch weckt App wenn neue HRV-Messung vorliegt (typisch nachts), kein Nutzereingriff
  • Aktiv: HKWorkoutSession für 5-Minuten On-demand-Messung, per Button triggerbar

4.4 Hintergrund-Sampling

Alle 5 Minuten (konfigurierbar) werden automatisch erfasst und in die lokale Queue geschrieben:

  • Ruhepuls, Aktivitätsklasse, aktueller Tremor-Score, Schritte letzte Stunde
  • SpO2 (Series 6+), Umgebungsgeräuschpegel (optional)

6.3 Offline-Queue

  • Alle Events zuerst lokal in SwiftData — Sync sofort wenn Netz verfügbar
  • Retry: exponentielles Backoff (30s → 60s → 120s → 300s → 600s)
  • Max Queue: 10.000 Events; bei Überlauf werden älteste verworfen (FIFO)
  • Queue-Status sichtbar in Complication und App-Status-Bar

9. Datenschutz & Sicherheit

🔒
Privacy by Design Keine Third-Party-SDKs, keine Analytics, keine Crash-Reporter die Daten senden. Alle Sensordaten verlassen das Gerät nur an den explizit konfigurierten Endpoint.
  • privacy.local_only_mode: true speichert ausschließlich lokal, kein Remote-Send
  • privacy.store_raw_motion: false (Default): nur aggregierte Metriken, keine Roh-Accelerometer-Daten
  • Token und Konfiguration im watchOS Keychain, nicht in UserDefaults
  • TLS 1.2+ erzwungen, Certificate Pinning optional konfigurierbar
  • HealthKit-Berechtigungen granular — nur angeforderte Typen
  • DSGVO-konform: kein Nutzer-Tracking, keine persistente Geräte-ID

11. Build & Deployment

GitHub Actions Workflow

# .github/workflows/build.yml
name: Build WatchLogger IPA
on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build:
    runs-on: macos-14
    steps:
      - uses: actions/checkout@v4
      - name: Select Xcode
        run: sudo xcode-select -s /Applications/Xcode_15.4.app
      - name: Import Signing Certificate
        env:
          CERTIFICATE_BASE64: ${{ secrets.CERTIFICATE_BASE64 }}
          CERTIFICATE_PASSWORD: ${{ secrets.CERTIFICATE_PASSWORD }}
        run: |
          echo "$CERTIFICATE_BASE64" | base64 --decode > cert.p12
          security import cert.p12 -k ~/Library/Keychains/login.keychain \
            -P "$CERTIFICATE_PASSWORD" -T /usr/bin/codesign
      - name: Build Archive
        run: |
          xcodebuild archive \
            -project WatchLogger.xcodeproj \
            -scheme WatchLogger \
            -archivePath build/WatchLogger.xcarchive \
            DEVELOPMENT_TEAM=${{ secrets.APPLE_TEAM_ID }}
      - name: Export IPA
        run: |
          xcodebuild -exportArchive \
            -archivePath build/WatchLogger.xcarchive \
            -exportPath build/ \
            -exportOptionsPlist ExportOptions.plist
      - name: Upload IPA
        uses: actions/upload-artifact@v4
        with:
          name: WatchLogger-IPA
          path: build/*.ipa
          retention-days: 30

Installation via AltStore PAL (EU, kostenlos)

  1. AltStore PAL aus dem App Store installieren (kostenlos in der EU seit DMA 2024)
  2. AltServer auf einem Windows-PC oder Mac installieren (einmalig)
  3. IPA-Artifact von GitHub Actions herunterladen
  4. In AltStore PAL: "+" → IPA auswählen → Installieren
  5. AltStore erneuert das Zertifikat automatisch solange AltServer im WLAN läuft
⚠️
Kein 99€/Jahr Apple Developer Account nötig Mit einem kostenlosen Apple ID + AltStore PAL (EU) ist das Sideloading dauerhaft kostenlos. Das Zertifikat muss alle 7 Tage erneuert werden — AltStore PAL macht das automatisch im Hintergrund.
